# Обмеження — що реально читається з FL Studio, а що ні

Принцип проєкту: **жодних вигаданих даних**. Усе, що показує presence, приходить з
офіційного FL Studio MIDI Scripting API (перевірено по документації FL 24 і на FL 24.2.2).
Memory scanning не використовується свідомо.

## ✅ Читається надійно (офіційний API)

| Дані | API | Примітка |
|---|---|---|
| FL запущений | heartbeat | зникнення >15 с = закритий |
| Версія FL + edition | `ui.getVersion(5)` | напр. `24.2.2 Producer` |
| Назва проєкту | `general.getProjectTitle()`, fallback `getProjectFilename()`* | *друга — недокументована, probing через `hasattr`; якщо обидва порожні — показується "Producing music" |
| Play / Pause / Stop | `transport.isPlaying()` | |
| Recording | `transport.isRecording()` | |
| Song mode / Pattern mode | `transport.getLoopMode()` | |
| Поточний pattern: номер | `patterns.patternNumber()` | |
| Поточний pattern: назва | `patterns.getPatternName(n)` | порожня, якщо патерн не перейменований |
| Вибраний канал: індекс, назва | `channels.selectedChannel(1)`, `getChannelName()` | |
| Плагін вибраного каналу | `plugins.getPluginName(ch)` | генератор channel rack'а |
| Вибраний mixer track: номер, назва | `mixer.trackNumber()`, `getTrackName()` | |
| BPM | `mixer.getCurrentTempo(1)` | |
| Позиція відтворення / довжина | `transport.getSongPos(SONGLENGTH_MS)`, `getSongLength()` | у снапшоті; у payload за замовчуванням не відображається |
| Метроном | `ui.isMetronomeEnabled()` | у снапшоті; шаблон-змінної нема |
| Розмір (чисельник) | `getRecPPB()/getRecPPQ()` | знаменник API не віддає |
| **Live MIDI: ноти, velocity, кількість** | `OnNoteOn` / `OnNoteOff` | основна фіча першої версії |

## ❌ Отримати надійно НЕ можна (і не емулюється)

1. **Ноти, які грає секвенсор/Piano Roll під час playback.** MIDI-скрипт бачить тільки
   live-вхід призначеного MIDI-пристрою. Ноти самою FL не проходять через скрипт ні в
   якому вигляді. Стабільного безпечного методу без memory reading нема — тому ця
   можливість не реалізована (presence показує live MIDI-гру, не вміст патернів).

2. **Live MIDI з інших пристроїв.** Скрипт отримує події лише того входу, на який він
   призначений. Граєте на другій клавіатурі — її нот у presence не буде. Також FL дозволяє
   **тільки один controller script на вхід**: якщо на клавіатурі вже висить Mackie/Fire
   скрипт, FLPresence і він не можуть бути на одному вході одночасно (варіант — віртуальний
   MIDI-кабель як окремий вхід).

3. **Назва пресету плагіна.** У API є `plugins.getName(..., FPN_Preset)`, але поведінка
   різниться між плагінами (VST2/VST3 часто віддають порожнє). Не використовується, щоб
   не показувати сміття.

4. **Ефекти на mixer track.** `plugins.getPluginName(track, slot)` для ефектів працює,
   але список ефектів вибраного трека в снапшот не включений (шум замість користі).

5. **Знаменник розміру (4/4, 7/8).** API віддає тільки чисельник.

6. **Swing, key/scale Piano Roll, кольори кліпів** — в API нема.

7. **"Хто грає зараз" при записі з мікрофону/ASIO-входу** — поза MIDI API.

## Поведінкові обмеження

- `OnDeInit` не викликається при kill процесу FL — тому присутність чиститься за
  heartbeat-таймаутом (15 с), а не миттєво.
- Якщо користувач не заповнив Title у F11 і білд FL без `getProjectFilename()`,
  назва проєкту буде порожньою ("Producing music") — API не дає шляху до .flp.
- Discord браузерний Rich Presence не показує; потрібен десктопний клієнт.
- Авто-призначення скрипта пишe registry FL лише коли FL закритий (FL перезаписує
  свої значення при виході).

## Виявлені особливості FL Studio (24.2.2) при інтеграції

Щоб скрипт узагалі з'явився у списку «Controller type» і запустився, потрібні всі три умови:

1. **`# name=<Назва>` у перших рядках .py** — без цього скрипт може працювати після
   ручного призначення, але ніколи не з'являється у випадаючому списку.
2. **`.ini`-маркер поруч зі скриптом** (`[Ini]` / `Version=2`) — інакше FL не показує
   папку у списку скриптів.
3. **Правильна тека користувацьких даних.** Тека FL Studio налаштовується
   (`HKCU\Software\Image-Line\Shared\Paths`, значення «Shared data») і на частині
   систем це НЕ Documents (наприклад, `C:\фл студио\`). FL показує список скриптів із
   теки з налаштувань, але призначені скрипти завантажує з Documents-дзеркала
   (`Documents\Image-Line\FL Studio\Settings\Hardware\...`) — тому FLPresence
   розгортає скрипт в обидві теки.

Діагностика «скрипт призначено, але мовчить»: `%APPDATA%\FLPresence\bridge_trace_*.log`
(трейс самого моста), вікно «Script output» у FL (View → MIDI Script output), кнопка
«Update MIDI scripts» у настройках MIDI (F10).

### Віртуальні MIDI-порти: скрипт не імпортується (виявлено 2026-09-25)

На FL Studio 24.2.2 build 4597 controller-скрипт **мовчки не імпортується** на
віртуальних MIDI-портах (перевірено і teVirtualMIDI, і loopMIDI). Систематична
перевірка з probe-логуванням на імпорті модуля: реєстрове призначення при boot-і,
ручний вибір «Controller type» у тій же сесії, «Update MIDI scripts»,
«Refresh device list», інжекція MIDI-нот у порт — імпорт не відбувається **жодного
разу**, при цьому призначення в UI видно, а пристрій матчиться за ім'ям. Debug-лог
FL (F10 → Debug) цього підтверджує: при старті логується «Opening MIDI output
devices», але «Opening MIDI input devices» при буті відсутнє, і жодного рядка про
завантаження/помилку скриптів немає — FL навіть не намагається. Єдиний випадок
успішного імпорту: **фізичний** MIDI-пристрій + призначення через UI.

Саме тому з v1.2.0 нативне джерело (процес + заголовок вікна FL) є базовим режимом:
воно не залежить від MIDI взагалі, а міст залишається опційним збагаченням для тих,
у кого є фізичний MIDI-пристрій.

## Advanced Integration (memory reading) — свідомо відсутня

Усе, що реально показується, доступне офіційним API, тому memory-reading шару немає
ні в якому вигляді — ні опціонального. Якщо колись знадобиться (наприклад, трекінг нот
секвенсора), його треба ізолювати в окремий version-gated модуль з AOB-сигнатурами
на кожен білд FL і м'яким вимкненням при невпізнанні — як це робить `nuiiv/FL-Studio-Discord-RPC`.
